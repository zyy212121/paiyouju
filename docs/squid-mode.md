# 鱿鱼模式

## 建房配置

创建房间时可勾选鱿鱼模式。人均结算额以 Initial Buy-in 的 `ceil(1/100)` 为基准，提供基准的 1–5 倍五个离散档位；普通模式不保存鱿鱼额度。模式和额度在房间生命周期内不可切换。

## 标记与轮次

- 每手只看主池。唯一赢得主池的玩家获得鱿鱼标记；主池平分时无人获得，边池不参与授标。
- 玩家普通中途坐下时以无标记状态加入当前轮。若已有未标记者确认离开、服务器已冻结本轮付款/收款集合，则此后才坐下者不追溯获标或收款，下一轮再成为正式参与者。
- 本手结算完成后，如果本轮参与者中恰好一人没有标记，该玩家向其余参与者每人支付建房时冻结的额度。
- 收付属于房间点数，不涉及 Wallet 钻石。付款后手不足时先自动补点以覆盖结算，补点进入本桌总带入和战绩；鱿鱼结算本身保持严格零和。
- 结算后清除全部标记、轮次加一，并进入 10 秒新轮提示期。提示期内可无惩罚站起；提示结束后再发下一手。
- 鱿鱼局的普通输光不会自动站起，而是在手末自动补到 Initial Buy-in 后继续。没有正额自动追加；只有达到零/负后手或强制结算不足时触发补点。

## 参与与离开

- 鱿鱼局不能使用保位离桌，也不能用暂停参与绕过轮次责任。
- 房间尚未正式开始、当前处于新轮 10 秒提示期，或玩家尚未进入当前轮结算集合时，站起不产生鱿鱼惩罚。
- 当前轮无标记者在其他时点站起，客户端显示应付说明并要求确认；确认后以该玩家为付款人立即完成本轮结算，再站起。
- 已有标记者站起时需确认放弃本轮收款资格；离开后清除标记。若因此只剩一名无标记者，服务器立即按剩余参与者结算，避免等待一手永远不会开始的牌。
- 活动手中请求站起仍遵循安全的本手后离桌；当前手余下行动进入让或弃，不再追加投入，手末按冻结的付款人与收款人完成结算。

## 托管

常驻托管与鱿鱼模式相互独立。玩家可随时在左上菜单开启“托管 · 让或弃”或取消；成为行动者后能 Check 就 Check，否则 Fold。小盲、大盲等强制投入属于开手规则，不被托管阻止。托管状态持久化并随重连/重启恢复。

## 一致性与恢复

Room 保存模式、额度、轮次、提示截止和待结算标志；Seat 保存标记、本轮参与资格与常驻托管。手末点数变更、结算账本、自动补点、Seat、Snapshot 和下一轮状态在同一 PostgreSQL 事务内提交。结算账本以稳定 operation key 防重，数据审计检查每次鱿鱼结算严格零和。TableSnapshot v3 完整恢复这些字段；健康 v2/v1 快照按普通模式、无标记、无常驻托管恢复。
