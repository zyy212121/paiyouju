# 普通模式“发两次”

## 开启边界

- 只允许创建普通模式房间时开启；鱿鱼及后续任何特殊模式都由服务端强制关闭。
- 只在一手牌最终仅剩两名未弃牌玩家、至少一人 All-in、已不存在后续合法下注且公共牌尚未发满时触发。
- 围观者和其他房间成员只能观看协商，没有投票权。

## 五秒协商

服务器建立绝对 5 秒截止时间。两名参与者都明确选择 `TWICE` 时可以立即结束协商并发两次；其余情况都等待完整 5 秒，截止时按发一次处理。玩家可在截止前修改自己的选择，命令使用独立 operation ID、expected state version 和 PostgreSQL 幂等回执。投票和 deadline 写入 Table Snapshot，重连或进程恢复不会延长时间或重复结算。

客户端只看到自己的选择和已经响应的用户列表，看不到对手具体选择。协商阶段没有普通 Poker legal actions。

## 牌堆与结算

已发出的公共牌是两副 Board 的共同前缀，不会收回牌堆。服务器从同一个剩余唯一牌堆先补满第一副，再从余牌补满第二副，因此两副新增公共牌互不重复。

每个规范化底池独立拆分：

```text
first = ceil(original / 2)
second = original - first
```

两副分别评牌、处理并列和奇数筹码。第一副获得底池拆分产生的额外 1 点；底池内部赢家平分产生的奇数筹码仍按 Button 左侧顺时针规则发放。两副派奖合并后更新真实最终后手，必须满足原 Hand 全部投入与全部派奖守恒。

## 桌面节奏

- 中央协商层显示发一次、发两次、本人当前选择、响应人数和倒计时。
- 确认发两次后显示上下两排各五张公共牌；共同前缀同时存在，两副新增牌依次按 Flop、Turn、River 展示。
- 第一副完成后停顿并显示该副 `YOU WIN`、`YOU LOSE` 或 `PUSH`，再开始第二副；第二副完成后显示第二个结果，然后进入既有手末观察阶段。
- 发牌阶段使用物理新增牌数驱动公共牌提示音，第二副不会因为复用第一副 Board 状态而静音；重新连接到已完成手不会补播整段动画或声音。

## 历史、看牌与删除

数据库保留一个 `HandRecord`，并以两个 `HandRunoutRecord` 及其逐副 Pot 记录保存权威结果。历史列表展开为 `<handNumber>-1`、`<handNumber>-2`；牌面、赢家、底池、行动金额和玩家结果按分支投影，两个分支逐字段相加还原原 Hand。

偷偷看授权绑定原 Hand，一次购买覆盖两个历史分支。发两次牌局已经保存两副完整真实公共牌，不提供发发看。房间永久删除、30 天保留清理、测试库清理和数据审计都先处理逐副 Pot/Board，再处理原 Hand。

## 核心回归

- 翻牌前、翻牌后和转牌后的双 Board；
- 短小盲直接 All-in 且大盲无需再行动；
- 同一剩余牌堆的牌唯一性；
- 每个奇数底池第一副多 1 点；
- 两票 `TWICE` 立即完成、任一 `ONCE` 或超时在完整 5 秒后发一次；
- 投票幂等重放、Snapshot 恢复、真实 PostgreSQL 两副记录；
- 历史 `N-1/N-2`、看牌授权共享、发发看拒绝及清理/审计。
