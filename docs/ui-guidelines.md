# Step 6.5 UI 与移动端规范

## 原创视觉边界

卡牌、牌背、牌桌、筹码/状态标记使用项目原创 React/CSS/SVG；花色使用系统 Unicode。通用界面图标使用 `lucide-react` 1.32.0（ISC）。提示音由项目原创 Web Audio 振荡器生成，没有下载第三方扑克品牌、图片或音效。

## 牌桌

- 主舞台锁定 `100dvh` 且 body 不滚动，不绘制明显圆/椭圆桌体。
- 2–9 人分别使用离散座位模板，不按圆周临时计算。
- 当前用户旋转到视觉底部，但 `seatIndex`、button、盲注和 actor 始终保留服务器权威索引。
- 375×812、390×844、430×932 下，边缘座位不裁切，关键控件至少 44px。
- 昵称截断而非撑开布局；最大 2,000,000,000 stack 仍应可读。
- Bet/Raise 输入只接受安全整数并 clamp 到服务端 legal action 范围；Raise 始终表示 Raise To 总额。
- 比例快捷加注点击即提交当前显示金额；主下注/加注按钮才打开精确金额滑杆与确认动作。
- Socket 断线、浏览器离线或命令 pending 时禁用写操作；不乐观修改筹码、pot 或 winner。
- 普通同步/拒绝提示最多显示 3 秒；新提示会取消旧提示的清理计时，`RECOVERY_ERROR` 等需要人工处理的持久错误不自动消失。

## 卡牌与隐私

可见卡牌使用用户可读 aria 名称（如 `A♠`）。内部牌码只存在于可见牌节点的 `data-card-code` 测试属性。`CardBack` 接口不接收牌码，aria 只暴露“隐藏底牌”；不得用 CSS opacity、翻面动画或条件样式隐藏已进入 DOM 的真实牌。

## 导航与可访问性

桌面顶部导航与移动端安全区底部导航均包含大厅、对局、手牌、Wallet、资料。使用 `focus-visible`、文字状态标签、accessible dialog、`aria-live` 回放说明和非纯颜色反馈。页面支持 `viewport-fit=cover` 与 safe-area inset。

登录/注册卡片只保留身份输入、提交动作和登录/注册切换，不显示重复的业务边界、阶段性短信说明或旧用户名切换行；移除内容后同步收紧间距，不保留空白占位。密码默认隐藏，独立 Eye/EyeOff 按钮以“显示密码/隐藏密码”切换输入类型，不能与“密码”输入标签产生可访问名称冲突。

动画只用于底牌两轮发牌、公共牌进入、Review/赢家和轻量状态过渡；`prefers-reduced-motion` 下直接取消运动，不延长任何 deadline。Web Audio 提示可本机关闭，播放失败不能阻塞操作。

## 浮层与占位

左右抽屉互斥且支持向外侧滑关闭，也可点击露出的桌面背景关闭；仅左侧排名/聊天入口可纵向拖动并只在本机保存位置，历史使用顶部固定按钮。抽屉的玩家/记录/聊天列表独立滚动，公共桌况、聊天输入及历史公共牌/翻页/偷偷看/发发看固定在底部。聊天气泡必须按座位方向避让顶部栏、Hero 和公共牌，最多显示 24 个 grapheme，长消息分段替换而不在气泡内滚动，且始终 `pointer-events:none`。菜单、购物车和加注器必须有明确焦点和 44px 触控目标；购物车直接打开补充后手托条，不经过钻石或其他二级菜单，坐下与站起玩家均可使用。首次坐下不弹窗，点空座领取房间 Initial Buy-in；之后重坐恢复原后手，0 Stack 自动站起后可先补点再重坐。以上均不扣钻石。钻石购买入口和桌面皮肤入口不显示；保险保持禁用占位。普通模式“发两次”协商层必须位于桌面中心且不遮挡 Hero，双排五张牌在 320px 宽度仍不得横向溢出，逐副结果按发牌顺序出现；精彩对局不显示。偷偷看和发发看只在历史界面提供。
