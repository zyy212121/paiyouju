# 牌友局产品规格（不可变基线）

状态：项目所有者持续维护的当前基线

实现状态：截至 2026-08-31，Step 0–Step 8、移动牌桌、管理后台、普通发两次、鱿鱼、短牌和暴击模式、本机 PostgreSQL 开发环境已实现；正式公网部署仍未执行。

产品界面名称：**牌友局**
项目目录代号：`wepoker`

## 1. 产品定位

牌友局是小规模、私人使用的 H5/PWA No-Limit Texas Hold'em 虚拟钻石娱乐平台，支持标准 52 张牌和明确授权的 36 张短牌模式：

- 总用户少于 500 人，同时在线通常少于 100 人。
- 单桌 2–9 人。
- 主要终端是 iPhone Safari 和 Android Chrome，并支持桌面 Chrome、Edge、Safari。
- 不开发原生 iOS 或 Android App。
- 房间不公开展示给陌生人，只能用房间码进入。

交互可借鉴通行扑克产品的一般逻辑，但不得复制第三方代码、Logo、商标、专有图片/音效、受版权保护素材或像素级设计。UI 暂只使用“牌友局”，不得出现 WePoker、AAPoker 等第三方商标。卡牌、桌面、筹码优先由自有 HTML/CSS/SVG 生成；使用图标库时必须确认并记录开源许可证。

当前不规定具体美术风格，也不把视觉精细度作为阶段验收门槛；但涉及的页面、状态和交互应尽可能完整。所需素材缺失或下载失败时，可使用明确标识的自制/许可证兼容占位素材，不得因此阻塞非美术功能。每个占位素材都要写入 `docs/asset-log.md`，记录原因、位置、来源/创建方式、许可证状态和替换条件。

## 2. 不可逾越的娱乐边界

所有钻石与筹码都是无现金价值的整数娱乐记分。系统只实现私人 No-Limit Texas Hold'em 桌及本文明确列出的玩法模式。

永久禁止：

- 充值、提现、银行卡、电子钱包、第三方支付或加密货币；
- 虚拟钻石兑换现金、真钱奖品、代理结算、俱乐部联盟或商业抽水；
- 保险、广告付费、大型锦标赛；
- Omaha、OFC；
- 语音聊天；
- rake、ante、straddle；普通模式双人 All-in 协商“发两次”是唯一获准的多次发牌能力。

Wallet 钻石和牌桌点数完全独立，不按任何比例转换或兑回。钻石只用于每手开局、偷偷看、发发看、行动加时和管理员受审计调整；牌桌点数只在当前房间生命周期中用于下注与输赢，离桌后只保留历史记录。

## 4. 房间配置与权限

创建房间时必须配置：

| 字段 | 约束 |
| --- | --- |
| 房间名称 | 必填，长度上限由边界 schema 固定 |
| 最大座位数 | 2–9 的整数 |
| Big Blind | 默认 20；快捷托条为 10/20/30/40/50，也可手动输入不小于 2 且严格低于默认带入/短牌下限的任意安全整数；Small Blind 不单独设置，由服务端取 `ceil(Big Blind/2)` |
| Initial Buy-in | 普通/鱿鱼/暴击桌使用，安全范围正整数且默认 2000；短牌桌不显示该项 |
| 短牌后手下限/上限 | 仅短牌桌使用，默认 500/2000；`Big Blind < 下限 <= 上限`，所有座位的上限总额不得超过全局安全上限 |
| 暴击频率 | 仅暴击桌使用；1 分钟快速档及 5–30 分钟每 5 分钟一档，默认 10 分钟 |
| 暴击盲注 | 仅暴击桌使用；1–10 BB 的整数档 |
| 行动时间 | 10–45 秒，每 5 秒一档；默认 30 秒 |
| 房间时长 | 30–180 分钟，每 30 分钟一档；默认 60 分钟，首次正式开始时开始倒计时 |
| 房间密码 | 可选；只能安全哈希保存 |
| 娱乐钻石服务 | 强制开启，不提供创建选项；基准 `x=10`，每手开局 `x`、偷偷看 `5x`、发发看 `x`、行动加时 `x`，全部与 BB 解耦 |

房间码必须不可预测、全局唯一且恰为 6 位数字。不得通过递增 ID、时间戳或弱随机数推导。即使有密码，用户也只能先用房间码定位房间。

房主只能查看房间信息、在满足条件时手动开始、暂停/恢复后续发牌、请求关闭房间。进行中的一手不会因关闭请求中断；关闭在结算及 Review 后执行。

## 5. 加入、座位、开局与离桌

加入房间只是获得房间会话，不自动坐下。同一用户在同一房间首次选择空座时，普通/鱿鱼/暴击桌领取固定 Initial Buy-in，短牌桌领取后手下限；之后站起、退出、保位、刷新、断线或换座都沿用同一 GameSession 和原后手，不再次领取。两手之间无论坐下或站起都可补充正整数点数；普通/鱿鱼/暴击桌单次上限为 Initial Buy-in，短牌桌补充后的后手不得超过上限。领取和补充都不改变 Wallet。

当至少两名玩家同时满足以下条件时，由房主明确开始；服务器不能仅凭人数自动开始首次牌局：

- 已坐下；
- 未暂停参与；
- Table Stack 大于 0；
- 已连接，或仍在服务端定义的允许恢复状态。

房主成功开始后，每手结算进入 4 秒 `POST_HAND_REVIEW`，统一展示赢家、结算和逐张亮牌。非强制摊牌玩家在 Review 内仍可逐张添加或撤回展示，所有更改由服务器事务提交并实时投影；下一手开始后清空。Review 结束且仍有至少两名合格玩家时直接开始下一手，不再插入第二个“等待下一手”阶段或重复开手倒计时。暂停或关闭会阻止后续发牌。人数不足时只停发、不停表；服务器每 30 秒复核一次，人数恢复后自动进入 5 秒开手倒计时。房主暂停优先且必须手动恢复。筹码低于 Big Blind 但大于 0 的玩家仍参加，以剩余筹码缴纳全下盲注；每名实际参与者在开手提交事务中另支付固定 10 钻石，余额不足时整手不创建且牌桌不得进入持久化故障状态。

房间创建后、首次正式开始前不倒计时。首次正式开始时由服务器写入开始时间，并按配置的 30–180 分钟计算唯一绝对截止时间；之后停发、暂停下一手、人数不足、退出、站起、保位离桌或重连均不暂停、不重置。到期不会中断当前手；当前手与 4 秒 Review 完成后强制停发并进入关闭流程。没有当前手时立即禁止开始；关闭分支只保留站起与离开能力。

离桌规则：

- 未参与当前手：立即把后手保存到活动 GameSession 并释放座位；
- 正参与当前手：标记 `leaveAfterHand`，结算后保存后手并释放座位；
- 已投入底池的筹码不会因刷新、断线或关页退回；
- 再次坐下恢复保存的后手，不新建 GameSession、不重复增加总带入；
- 只有房间最终关闭时才一次性记录最终牌桌点数并关闭 GameSession；重复关闭不得重复结算，任何路径都不增加 Wallet。

### 5.1 玩法模式

- 创建房间时，“All-in 后发两次”、鱿鱼模式、短牌模式和暴击模式互斥。普通模式可单独开启发两次；任何特殊模式开启时服务端强制关闭发两次。启用的玩法都在左上菜单提供当前规则说明；纯普通局的规则按钮保持不可用。
- 短牌的牌桌 UI、盲注、下注和操作逻辑与普通局一致。牌组只含 6 到 A 共 36 张牌，A-6-7-8-9 是最小顺子；同花大于葫芦，顺子仍大于三条，其余比较沿用标准德州扑克。
- 短牌每手先完成真实零和的 Poker 结算，再在同一数据库事务中规范后手：低于下限自动补至下限，高于上限自动退至上限。补点计入 `totalBuyIn`，退点计入 `totalCashOut`，实时战绩使用 `当前后手 + totalCashOut - totalBuyIn`；二者都只属于牌桌点数，不接触 Wallet 钻石。
- 暴击计时从首次正式开始运行，使用 1、5、10、15、20、25、30 分钟档。牌桌中央显示下一次暴击倒计时，到期后改为“下一手暴击”。到期后的下一手由所有参赛者（包括原大小盲）各自强制投入同一个 1–10 BB 目标额，不叠加普通大小盲，随后直接发 Flop。后手不足者投入全部后手。完整规则见 `docs/bomb-pot-mode.md`。

## 6. 超时与连接状态

行动截止时间由服务器产生和执行，客户端只根据服务器时间信息显示。

- 超时时当前合法动作包含 Check：服务器自动 Check。
- 不能 Check：服务器自动 Fold。
- 断线不离桌、不停发、不在手末自动暂停；座位保持 `ACTIVE` 并继续参加后续手牌。
- 断线期间临时按常驻“让或弃”托管处理：轮到时能 Check 就立即 Check，否则 Fold，强制盲注仍正常投入。
- 重连后：先恢复权威快照，再恢复正常人工行动；玩家主动开启的常驻托管不因重连自动取消。
- 客户端明确显示“已连接 / 正在重连 / 已断开”；离线时不得显示未经服务器确认的成功动作。
- 当前行动者最后 3 秒显示独立紧急倒计时。加时无需确认，支付固定 10 钻石后把服务器 deadline 延后初始行动时间的一半；余额足够时可重复使用，余额不足时点击不产生写操作或提示。

## 7. 历史、回放与隐私

用户可在 30 天保留期内查看自己参加过的房间对局、入桌/点数领取/离桌/净结果；进入房间后可查看该房间全部已结算手牌的公共牌、公开底牌、每轮行动、主/边池与获胜者。实际参与者另见自己的底牌、起止点数与净结果，围观者对应字段为空。

用户不可查看未公开且未购买的底牌、未来牌、洗牌顺序或服务器完整牌堆。简单回放从经过权限过滤的持久化领域事件重建，不泄漏事件中仍属私密的牌。

所有已经提交的牌桌点数都必须通过主池或边池派奖；新完成手不记录未匹配退款。两人 10/20 盲注中小盲投入 10 后弃牌时，主池为 30、大盲获得 30。All-in 结算若存在只有一名未弃牌贡献者覆盖的最高投入层，该层保存为只由该玩家获胜的锁定末层池。

结算展示把每个正数 `POT_AWARDED` 赢家和正数 `UNCALLED_BET_RETURNED` 收款人都视为本手获奖玩家；本人属于该集合时显示 `YOU WIN`。牌桌按每个派奖/退回目标播放筹码从底池归置到对应座位的短动画，整批动画播放一次 `chipfly`，原有胜利音仍只对本人获奖时播放。

管理员只能为审计访问完整牌局；后台所有敏感查看需要角色权限，并写不可抵赖的审计记录。

## 8. 钻石看牌

钻石看牌只允许整手已结算且 Review 结束后发生。购买者必须是该房间成员且 Wallet 足额；参与者与围观者均可购买，管理员不能脱离房间成员身份代看；该手至少存在一名仍隐藏底牌的参与者。

一次购买的业务唯一键为 `(buyerUserId, handId)`，新手牌冻结费用为 50 钻石，授权该买方查看整手所有隐藏底牌。扣除 Wallet 与创建查看授权必须在同一数据库事务中完成；唯一约束保证重试不重复扣费。Step 6 任意旧逐目标授权视为整手授权，不再次收费；既有完成手保留当时冻结的历史费用。费用从系统中消耗，不进入任何房主或玩家账户。

结果只返回购买者本人、不向全桌广播、不改变公共历史。授权在该手仍处于 30 天保留期时显示在购买者自己的历史详情，其他玩家继续不可见。管理员只能为审计读取保留期内的购买记录。

## 9. Step 6.5 生命周期补充

- 等待预操作包含可反悔的“让或弃”和“自动跟注”。让或弃为 `Check else Fold`，本街最高投入变化后仍保持；自动跟注只绑定玩家点击时的最高投入和待跟金额，金额变化即取消，绑定未变时只 Call 一次，绝不自动 Bet/Raise/All-in。保位离桌仍只使用 `Check else Fold`，期限为服务端 60 秒。
- 点击空座时，普通/鱿鱼桌首次入座领取 Initial Buy-in，短牌桌首次入座领取后手下限，之后入座均恢复该房间保留后手；都不弹首次买入表单，Wallet 钻石为 0 也可坐下。购物车直接打开补充后手托条，不设置钻石或二级菜单；托条为 10 个离散档位并默认最大档，普通/鱿鱼桌单次最大值为 Initial Buy-in，短牌桌可用最大值为当前后手到上限的差额。站起并保留活动 GameSession 的玩家同样可以补充。未入座时不渲染 Hero 说明框。
- 普通模式 stack 归零在 Review 清理后自动站起并保留同一活动 GameSession；再次坐下以 0 Stack 进入待补点状态，不重复领取 Initial Buy-in。鱿鱼和短牌按各自规则在同一结算事务中自动补点，不因本手输光自动站起。
- 进行中的一手允许玩家分别点击两张本人底牌，切换私人“待亮”状态；未选牌正常显示，已选牌只使用小型半透明 Eye/暖色标识。进入 Review 后仍可逐张添加或撤回展示，已展示牌位于头像区且可点击撤回；强制 Showdown 牌不接受更改，下一手开始清空全部待亮状态。
- 每手结算持久化唯一五张 `fullBoard`；普通牌桌/历史只公开实际 Board，“发发看”首次触发后公开该手的隐藏后缀并保存唯一结果，所有购买者和后续页面切换一致。
- CLOSED 且无活动座位/会话的房间可以软归档并从列表隐藏；关闭满 30 天后，房间、牌局、玩家、牌桌点数流水、授权和关联审计由后台保留任务物理删除。账户与 Wallet 当前余额不随历史清理删除。
- 手机号只作登录标识，没有短信验证、号码归属验证或实名认证；公共 DTO 只提供掩码。
- 钻石购买、桌面皮肤和保险入口均不提供。普通模式可在创建房间时启用“发两次”，特殊模式强制关闭；双人 All-in 通过 5 秒一致协商决定，历史拆为 `<手数>-1/-2`。历史中的“精彩对局”入口已删除。房间文字聊天已开放：参与者与围观者权限相同，单条 120 个可见字符、最近 50 条为进程内临时历史，支持原生 Emoji，不提供永久禁止的语音聊天。

钻石看牌和发发看只在历史抽屉或历史详情出现；结算观察层不提供入口。左右抽屉支持向屏幕外侧滑关闭，也可点击露出的桌面背景关闭；仅左侧排名/聊天入口可纵向拖动并记住位置，历史使用顶部固定按钮，不再显示右侧悬浮入口。左抽屉提供按盈亏降序的本桌排名、入池率、胜率、总带入、离桌玩家开关和固定底部公共桌况，不显示活跃度积分；聊天列表独立滚动、输入和 Emoji 区固定在底部。已入座玩家的新消息在头像外侧显示气泡，每段最多 24 个可见字符并依次替换而非在气泡内滚动；右抽屉把历史公共信息和看牌/发发看操作固定在底部，玩家详情独立滚动。

## 10. Stage 0 验收边界

Stage 0 只建立目录、架构、不可变文档和可验证工程：开发首页、`/health`、shared 引用、空 poker-core 测试、严格检查、最小 Prisma、PostgreSQL Compose、Caddy/Docker、Windows 说明。不得实现牌、牌桌、用户、房间、Wallet 或 Socket.IO 业务。

## 11. Step 7 运维边界

Step 7 增加 `/admin`、AuditLog、安全钻石调整、生产 Docker/Compose/Caddy、外部备份、恢复演练、只读数据审计和 CI，不改变扑克产品语义。管理员无权改活动牌、牌堆、Pot、Stack、赢家或 Snapshot。系统仍为虚拟娱乐钻石、单活动应用实例、无短信/支付/真钱；本阶段未实际公网部署。
