# 发牌、公共牌与音效协调

## 动画事件

新 `handId` 触发两轮底牌发牌：统一牌背从中央按参与者顺序移动到座位；对手始终只收到/显示牌背，Hero 两张牌先以牌背落位，再按顺序逐张翻出已授权牌面。Board 长度从 0→3、3→4、4→5 时，新增公共牌也先逐张显示牌背，再按顺序翻到正面；不再用一层重复的飞牌覆盖真实 Board。

协调器以 `handId + board.length + actionHistory.length` 识别已表现事件。普通行动和已经完整展示的牌局在刷新/重连后按当前权威快照直接落位；若快照仍处于 All-in 自动补牌的结算展示窗口，则从行动记录中最后一个正常公开街道继续呈现，不能借刷新提前看到河牌或结果。动画队列不会修改状态、发送命令、延长行动 deadline 或阻塞操作。

All-in 自动补全 Board 时，服务端仍在一个事务中完成结算和持久化，保证进程异常后不会出现“牌已发但结果未记”的半状态；客户端增加独立的结算展示投影。Flop、Turn、River 尚未全部翻完时，座位后手保持为 `startingStack - committedThisHand`，隐藏赢家、派奖事件、最终牌型、结算框和鱿鱼新轮提示。最后一张公共牌完成后，这些字段一次切换到权威结算值。因此动画只延迟可见结果，不延迟或伪造数据库事务，也不会提前泄漏输赢。

## Reduced motion 与音效

`prefers-reduced-motion: reduce` 时取消移动、翻转、缩放和循环脉冲，状态仍立即完整出现。音效使用浏览器 Web Audio 生成短促原创提示：发牌、公共牌、筹码、轮到自己、菜单和获胜。声音默认开启，可在本机切换；唯一持久键是 `wepoker.table-sound.enabled`，不保存牌、手机号、房间或 Session。

Audio 创建/播放失败属于增强能力失败，必须静默降级且不能阻止扑克命令。项目没有复制、下载或打包第三方扑克音效。

任何 Bet、Raise 或 Call 若恰好投入玩家全部剩余后手，领域事件统一为 `PLAYER_ALL_IN`。座位状态和真人语音都播放“全下”，不会因玩家点击的是快捷加注或跟注入口而误播“加注”。
